# Resources

Resources setup and configuration
follows [compose-multiplatform-resources](https://kotlinlang.org/docs/multiplatform/compose-multiplatform-resources.html).

## Strings

Strings live in `core/strings/src/commonMain/composeResources/values/strings.xml` in `:core:strings`
module.

Group entries in `strings.xml` by feature under a `<!-- Feature name -->` comment, in the
same order the features appear. `app_name` is the one exception to the naming rule.

Two things are *not* UI strings and must stay hardcoded: test tags and non-textual glyphs
used as icons. Test tags live in a `<Feature>Tags` object in its own file in the same `…ui` package
as the UI that applies them,
and stay public so end-to-end tests can address nodes without repeating the literals.

Gradle's `api()` and `export()` can be used for tags that need to be exported to the iOS
framework, so the Swift end-to-end tests can address the same nodes.

### Strings naming

Three underscore-separated parts: **feature** + **UI element** + **text type/purpose**.

```
main_menu_add_button_label
note_editor_title_field_label
settings_theme_dark_label
user_profile_general_info_title
transactions_header_description
```

### Placeholders

Prefer strings with placeholder parameters instead of concatenating multiple strings together
in code.

### Rich text

Prefer annotated strings with different span styles over combining multiple separate `Text`
elements.

## Icons

Icons are stored in `:core:design` composeResources directory in Android XML format, Kotlin
accessors are generated by Compose.

## Dimens

Dimens are stored in `:core:design` in code as `object` properties.
